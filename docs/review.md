# 实现与发布审查

审查日期：2026-08-31。目标是确认现有实机方案可维护、可复现，并能安全公开。

## 结论

`MJTD04YL → ESP32-C3 → ESPHome → Home Assistant` 的主链路已经通过实机验证。组件完成 P-256 会话协商、HKDF-SHA256 派生、AES-CCM 登录与命令加解密，HA 侧可以控制开关、亮度和色温。OLED 只是同一网关配置上的可选显示层。

## 本次修正

| 发现 | 风险 | 处理 |
|---|---|---|
| API 加密密钥原先直接写在入口 YAML | 公开仓库会泄密 | 迁移到本地 `secrets.yaml` |
| MAC、热点密码、HA 实体 ID 混在公开配置 | 难复用并暴露家庭信息 | 全部模板化或移入 secrets |
| OTA 没有密码 | 同网段可尝试未授权升级 | 增加独立随机 OTA 密码 |
| OLED 与网关核心写在同一大文件 | 难拆纯网关，后续易分叉 | 抽出共享 package，增加 headless 入口 |
| 协议保留未工作的 GET 路径 | 死代码造成误解与超时 | 删除 GET 命令分支 |
| BLE FlowPacket 帧数没有上限 | 异常输入可能扩大内存占用 | 公钥限制 8 帧、命令限制 16 帧 |
| 两个登录阶段未校验 ACK 内容 | 异常通知可能推进状态机 | 校验 `00000100` ACK |
| 运行数据和第三方集成副本处于项目目录 | 容易误提交 | 扩展 `.gitignore` 并仅提交通用配置 |

## 验证证据

- `esphome config`：OLED 与纯网关配置均通过。
- `esphome compile`：ESPHome 2026.8.1 下两份固件均完成链接并生成 factory/OTA 映像。
- 纯网关：Flash 约 79.0%，DRAM 约 43.1%。
- OLED：Flash 约 81.1%，DRAM 约 43.5%。
- 实机回归：登录成功后，开关、亮度、色温命令均收到加密设备 ACK 或结果包。
- Home Assistant：light 实体和本地连接诊断实体均可见。

## 安全边界

LTMK 是每台设备独有的长期秘密，ESPHome API key 与 OTA password 也是控制凭据。它们会进入本地固件，因此源码仓库可以公开，带真实 secrets 编译的二进制不能公开。

QR 登录辅助脚本使用小米账号网页流程，不接收命令行密码；token 只保存在进程内存中。脚本仍依赖非官方接口，使用者应自行评估账号风险。

## 已知限制

- 未对其他 Xiaomi BLE Mesh 灯具做兼容性声明。
- 尚无协议级单元测试夹具；主要验证仍依赖真实设备与编译检查。
- 设备直接 GET 在 `lamp21` 上没有可靠响应，断线期间的物理操作可能等到下一次设备通知或 HA 命令才同步。
- 自定义外部组件不在 ESPHome 官方安全支持范围内。
